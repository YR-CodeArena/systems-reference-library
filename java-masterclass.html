1. Execution Model, JDK/JRE/JVM & First Program

FIGURE 12.1 // JVM RUNTIME

JVM Classloader Hierarchy & Delegation Architecture

1.1 Conceptual Deep Dive & Execution Pipeline

Java is a high-level, class-based, object-oriented programming language designed around the core philosophy of "Write Once, Run Anywhere" (WORA). Unlike traditional purely compiled languages (like C or C++) which compile directly into platform-specific machine code (binary instructions unique to an x86 or ARM CPU), Java uses a two-stage translation pipeline involving both compilation and interpretation.

When a developer writes code in a file named Main.java, this file contains human-readable Java syntax. The Java Compiler (javac) compiles this source code into an intermediate format called Bytecode, stored in a Main.class file. Bytecode is not machine code for any real computer hardware; instead, it is an optimized set of instructions for an abstract machine called the Java Virtual Machine (JVM).

When executing the application, the JVM loads the .class file and translates bytecode instructions into native machine code on the fly using a combination of an Interpreter and a Just-In-Time (JIT) Compiler. The Interpreter reads bytecode instructions line by line and executes them. However, when the JVM detects "hot spots" (frequently executed code paths, such as loops), the JIT compiler compiles those bytecode segments into native machine instructions directly executed by the host CPU, drastically accelerating execution speed.

1.2 Architecture Stack: JDK vs. JRE vs. JVM

To understand the Java runtime ecosystem, one must differentiate between the three core architectural layers:

  • JVM (Java Virtual Machine): The core execution engine. The JVM manages application memory (Stack and Heap), handles automatic garbage collection, enforces security boundaries, and executes bytecode. There are platform-specific JVM implementations for Windows, macOS, Linux, Android, etc.
  • JRE (Java Runtime Environment): The distribution package necessary to run a compiled Java program. It encompasses the JVM along with the core Java Class Libraries (e.g., java.lang, java.util, java.io) and support files. It does not contain compilation tools.
  • JDK (Java Development Kit): The full-featured software development environment required to create and compile Java applications. The JDK contains the JRE, the Java compiler (javac), the archiver (jar), documentation generators (javadoc), and debugging utilities (jdb).

1.3 Anatomy of the Main Method

Every standalone executable Java application requires an entry point signature matching the exact declaration:

java • Main.java 
public class Main {
    /**
     * Entry point of the Java Application.
     * @param args Command-line arguments passed to the application.
     */
    public static void main(String[] args) {
        // Output statements
        System.out.println("Hello, World!");
        System.out.print("Execution finished without new line.\n");
    }
}

Let's dissect each keyword of public static void main(String[] args):

  • public: An access modifier specifying that the method can be invoked from anywhere outside its class package. The JVM launcher must call this method from the host operating system context.
  • static: Indicates that the method belongs to the class itself, rather than an object instance of the class. This allows the JVM to invoke main() directly without allocating memory for an instance of the Main class first.
  • void: The return type, specifying that this method does not return any value back to the caller upon completion.
  • main: The exact method name searched for by the JVM class loader.
  • String[] args: An array of String objects representing command-line parameters passed into the application at execution time (e.g., java Main arg1 arg2).

1.4 Console Output & Escape Sequences

Java handles console output via System.out, which is an instance of java.io.PrintStream:

  • System.out.print(): Outputs the specified text string to the console without moving the output cursor to a new line.
  • System.out.println(): Outputs the specified text string and automatically appends a platform-specific newline sequence, moving the cursor to the beginning of the next line.
Escape Sequence Name Description & Behavior
\n Newline Moves the output cursor to the start of the next line.
\t Tab Inserts a standard horizontal tab space (typically 4 or 8 spaces).
\" Double Quote Escapes a literal double quote inside a String literal without closing it.
\\ Backslash Inserts a single literal backslash character into the output string.
\r Carriage Return Moves the cursor back to the start of the current line, overwriting prior text.

2. Memory Architecture & Primitive/Reference Types

2.1 Stack vs. Heap Memory Allocation

Java divides runtime RAM memory into distinct region architectures managed directly by the JVM:

text 
STACK MEMORY                                  HEAP MEMORY
(Thread-Private, Fast, LIFO)                  (Shared, Dynamic Allocation)
+----------------------------------------+    +------------------------------------+
| main() Frame                           |    |                                    |
|  - primitive int age = 25              |    |  String Object                     |
|  - primitive double gpa = 3.85         |    |  [ Value: "SpongeBob" ]            |
|  - reference nameRef ------------------+--->|  Address: @0x7f8a9                 |
|                                        |    |                                    |
+----------------------------------------+    |  Array Object                      |
| calculate() Frame                      |    |  [ 10, 20, 30 ]                    |
|  - local int temp = 100                |    |  Address: @0x3b1c2                 |
+----------------------------------------+    +------------------------------------+

Stack Memory: Each thread in a Java application possesses its own private Stack. Stack memory operates on a Last-In, First-Out (LIFO) frame basis. Whenever a method is called, a new Stack Frame is created containing all local variables and primitive values declared within that method. When the method returns, its stack frame is instantly popped and deallocated.

Heap Memory: A single, globally shared pool of memory accessible by all application threads. All runtime objects (e.g., custom class instances, arrays, Strings) are dynamically allocated on the Heap using the new operator. Objects on the Heap remain alive until they are no longer referenced anywhere on the Stack, at which point they become eligible for automatic cleanup by the Garbage Collector (GC).

2.2 Primitive vs. Reference Types

Java enforces a strict distinction between primitive data types and reference data types:

Data Type Size (Bits/Bytes) Stored Value / Representation Default Value Valid Value Range
byte 8 bits / 1 byte Signed 2's complement integer 0 -128 to +127
short 16 bits / 2 bytes Signed 2's complement integer 0 -32,768 to +32,767
int 32 bits / 4 bytes Signed 2's complement integer 0 -2,147,483,648 to +2,147,483,647 (~2 Billion)
long 64 bits / 8 bytes Signed 2's complement integer 0L -9,223,372,036,854,775,808 to +9,223,372,036,854,775,807
float 32 bits / 4 bytes IEEE 754 floating-point 0.0f ~6-7 significant decimal digits (Requires f suffix)
double 64 bits / 8 bytes IEEE 754 floating-point 0.0d ~15-17 significant decimal digits (Standard precision)
char 16 bits / 2 bytes Unsigned UTF-16 Code Unit '\u0000' 0 to 65,535 (Single characters enclosed in ' ')
boolean 1 bit (Logical) Truth state (JVM dependent) false Literals: true or false
The "Money Analogy" for Primitive vs. Reference Types

A primitive variable is like cash directly in your wallet—the variable name directly holds the exact numerical value on the Stack. A reference variable is like a bank slip with an address written on it—the variable on the Stack does not contain the object's actual data; it contains a 64-bit memory address pointing to where the real Object data resides on the Heap.

java • DataTypesDemo.java 
public class DataTypesDemo {
    public static void main(String[] args) {
        // Primitive Declarations (Stored directly on the Stack)
        byte age = 25;
        int views = 1_500_000; // Underscores improve readability
        long worldPopulation = 8_000_000_000L; // 'L' suffix required for long literals
        float temperature = 36.6f; // 'f' suffix required for float literals
        double accountBalance = 9999.99;
        char grade = 'A';
        boolean isEnrolled = true;

        // Reference Declaration (Reference on Stack pointing to Heap String Object)
        String studentName = "SpongeBob";

        System.out.println("Student: " + studentName + " | Age: " + age);
        System.out.println("Population: " + worldPopulation);
    }
}

3. User Input via Scanner & Buffer Management

3.1 Understanding java.util.Scanner Mechanics

The Scanner class parses primitive data types and strings from input streams using regular expressions. To read input from the console, developers wrap the standard input stream (System.in) inside a Scanner object instance:

java 
Scanner scanner = new Scanner(System.in);

3.2 The Input Buffer Trap & Solution

One of the most common pitfalls faced by Java developers involves mixing token-based parsing methods (e.g., nextInt(), nextDouble()) with line-based parsing methods (nextLine()).

text 
User types "25" and presses [ENTER] on the Keyboard:

INPUT BUFFER STATE:
+-----+-----+------+
| '2' | '5' | '\n' |   <-- '\n' is the newline character generated by pressing Enter
+-----+-----+------+

1. scanner.nextInt() is called:
   - Consumes '2' and '5' -> Converts to integer value 25.
   - LEAVES '\n' sitting inside the Input Buffer!

2. scanner.nextLine() is called immediately after:
   - Scans the Input Buffer for text up to the next '\n'.
   - Finds '\n' IMMEDIATELY -> Assumes user pressed Enter without typing!
   - Returns an EMPTY String ("") and skips user prompting!
The Buffer Cleanup Rule

Whenever you invoke nextInt(), nextDouble(), nextFloat(), or next(), and plan to call nextLine() subsequently, you MUST clear the leftover newline character by invoking an unassigned scanner.nextLine(); call in between.

java • ScannerBufferFix.java 
import java.util.Scanner;

public class ScannerBufferFix {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter your age: ");
        int age = scanner.nextInt(); // Reads integer, leaves '\n' in buffer

        // --- BUFFER CLEARING STEP ---
        scanner.nextLine(); // Consumes the leftover newline character '\n'

        System.out.print("Enter your favorite color: ");
        String color = scanner.nextLine(); // Now successfully waits for user input!

        System.out.println("Age: " + age + " | Color: " + color);
        scanner.close(); // Releasing system input resources
    }
}

4. Arithmetic Operators, Type Promotion & Order of Operations

4.1 Arithmetic & Modulus Operators

Java supports five standard binary arithmetic operators: Addition (+), Subtraction (-), Multiplication (*), Division (/), and Modulus (%).

The Modulus Operator (%) computes the remainder of an integer division operation. For instance, 10 % 3 yields 1 because 3 divides into 10 three times (giving 9), leaving a remainder of 1.

  • Parity Detection: Check if a number is even (num % 2 == 0) or odd (num % 2 != 0).
  • Cyclic Array Indexing: Keep array bounds wrapping around smoothly: index = (index + 1) % arrayLength.

4.2 Integer Division vs. Floating-Point Division

When performing division between two integer types (byte, short, int, long), Java performs Integer Division, truncating all fractional decimals without rounding:

java • DivisionDemo.java 
int a = 10;
int b = 4;
int result1 = a / b; // Evaluates to 2! The .5 decimal is completely dropped.

// To retain exact floating-point precision, explicitly cast at least one operand:
double result2 = (double) a / b; // Evaluates to 2.5

4.3 Pre-Increment vs. Post-Increment Semantics

  • Post-Increment (x++): Evaluates the variable's current value in the surrounding expression first, and then increments the value of x by 1 afterwards.
  • Pre-Increment (++x): Increments the value of x by 1 first, and then evaluates the newly updated value within the surrounding expression.

5. Control Flow, Decisions & Enhanced Switches

5.1 Conditional Decision Execution (if-else if-else)

Conditional ladders evaluate logical expressions sequentially from top to bottom. As soon as a single condition evaluates to true, the corresponding block executes, and the remainder of the conditional branch is bypassed entirely.

5.2 The Ternary Operator (? :)

A concise operator used as a shorthand replacement for simple assignment if-else structures:

java 
variable = (condition) ? value_if_true : value_if_false;

5.3 Enhanced Switch Expressions (Java 14+)

Modern Java introduced Enhanced Switch Expressions using the arrow operator (->). Advantages over legacy fall-through switches:

  • No explicit break; statements required—eliminates accidental fall-through bugs.
  • Allows comma-separated grouping of multiple match labels.
  • Can be used directly as expressions that return values into variables.
java • EnhancedSwitchDemo.java 
public class EnhancedSwitchDemo {
    public static void main(String[] args) {
        String day = "Wednesday";

        // Enhanced Switch Statement using Arrow Syntax
        switch (day) {
            case "Monday", "Tuesday", "Wednesday", "Thursday", "Friday" -> 
                System.out.println("Weekday - Time to work!");
            case "Saturday", "Sunday" -> 
                System.out.println("Weekend - Time to relax!");
            default -> 
                System.out.println("Invalid day string specified.");
        }

        // Switch Expression Returning a Value
        int quarter = switch (day) {
            case "Monday", "Tuesday", "Wednesday" -> 1;
            case "Thursday", "Friday" -> 2;
            default -> 0;
        };

        System.out.println("Quarter: " + quarter);
    }
}

6. Logical Operators & Random Number Generation

6.1 Logical Operators & Short-Circuit Evaluation

  • && (Logical AND): Evaluates to true only if both operands are true.
  • || (Logical OR): Evaluates to true if at least one operand is true.
  • ! (Logical NOT): Inverts the boolean truth state of an expression.

Short-Circuit Behavior

For A && B, if A is false, B is never evaluated because the entire statement is guaranteed to be false. For A || B, if A is true, B is skipped completely. This prevents NullPointerExceptions (e.g., if (obj != null && obj.isValid())).

6.2 Pseudo-Random Numbers (java.util.Random)

java • RandomDemo.java 
import java.util.Random;

public class RandomDemo {
    public static void main(String[] args) {
        Random random = new Random();

        // Bound parameter: nextInt(origin, bound) -> Inclusive of origin, EXCLUSIVE of bound
        int diceRoll = random.nextInt(1, 7); // Generates integer between 1 and 6
        double percentage = random.nextDouble(); // Generates 0.0 to 1.0
        boolean coinFlip = random.nextBoolean(); // Generates true or false

        System.out.println("Dice Roll: " + diceRoll + " | Coin: " + coinFlip);
    }
}

8. String Manipulation & String Slicing

8.1 String Immutability & The String Constant Pool

Strings in Java are immutable. Once a String object is instantiated on the Heap, its internal character array cannot be modified. Any modification method (e.g., toUpperCase(), replace()) returns an entirely new String reference on the Heap.

To optimize memory usage, Java utilizes a String Constant Pool inside the Heap. When literal strings are created (String s1 = "Java";), Java checks the pool first. If the literal exists, it reuses the reference rather than creating a new object.

The Absolute String Equality Rule

NEVER compare String values using the == operator! The == operator checks if two reference variables point to the same memory address on the Heap. To compare actual character content, always use .equals() or .equalsIgnoreCase().

8.2 String Slicing Demo

java • StringSlicingDemo.java 
public class StringSlicingDemo {
    public static void main(String[] args) {
        String email = "developer_user@java.org";

        // Substring Extraction Syntax: substring(beginIndex, endIndex) -> endIndex is EXCLUSIVE
        int atIndex = email.indexOf("@");
        if (atIndex != -1) {
            String username = email.substring(0, atIndex);
            String domain = email.substring(atIndex + 1);
            System.out.println("User: " + username + " | Domain: " + domain);
        }
    }
}

9. Iteration & Loops

9.1 Comparison of Java Loop Structures

  • while loop: Evaluates condition before entering block. Executes 0 or more times.
  • do-while loop: Executes block once first, then checks condition. Executes 1 or more times.
  • for loop: Best when iteration counts are known beforehand. Syntax: for (init; condition; update)

9.2 Control Flow Keywords (break & continue)

  • break: Instantly terminates the loop structure completely, jumping execution outside the loop.
  • continue: Halts processing of the current cycle and skips directly to the next iteration check.
java • LoopsDemo.java 
public class LoopsDemo {
    public static void main(String[] args) {
        // Demonstrating continue and break
        for (int i = 1; i <= 10; i++) {
            if (i == 5) continue; // Skip iteration when i is 5
            if (i == 8) break;    // Terminate loop completely at 8
            System.out.print(i + " ");
        }
        // Output: 1 2 3 4 6 7
    }
}

10. Methods & Method Overloading

10.1 Anatomy of a Java Method

A method is a named block of code that performs specific tasks and is executed upon call invocation.

  • Parameters: Formal variables declared in the method signature header.
  • Arguments: The concrete values passed into the method during invocation.
  • Pass-by-Value: Java is strictly pass-by-value! Primitive arguments pass copies of their values. Reference arguments pass copies of their memory addresses.

10.2 Method Overloading Principles

Method Overloading occurs when multiple methods within the same class share the exact same method name, but have different parameter signatures (different number, types, or ordering of parameters). Changing only the return type does NOT overload a method and causes a compilation error!

java • OverloadingDemo.java 
public class OverloadingDemo {
    public static void main(String[] args) {
        System.out.println(add(10, 20));        // Invokes method 1
        System.out.println(add(10.5, 20.5));    // Invokes method 2
        System.out.println(add(1, 2, 3));       // Invokes method 3
    }

    public static int add(int a, int b) { return a + b; }
    public static double add(double a, double b) { return a + b; }
    public static int add(int a, int b, int c) { return a + b + c; }
}

11. Variable Scope, Lifetime & Shadowing

Scope dictates where a variable is accessible within code boundaries:

  • Local Scope: Variables declared inside a block or method. Exist on the Stack and disappear when the block scope terminates.
  • Class Scope (Fields): Variables declared inside a class body but outside methods. Accessible across class instance/static contexts.
  • Variable Shadowing: Occurs when a local variable declared inside a method shares the exact name as a class-level variable. The local variable "shadows" the class variable within that method scope. Use this.fieldName to explicitly reference the class variable.

12. Arrays, Operations & Varargs

12.1 1D Arrays & Memory Allocation

An array is a fixed-size reference data type allocated on the Heap storing elements sequentially.

public class ArrayOperations {

13. OOP Fundamentals: Classes, Objects & Static

13.1 Objects, Constructors & this Keyword

  • Class: Blueprint template defining properties and behaviors.
  • Object: Concrete instance instantiated on the Heap using new.
  • Constructor: Special initialization method matching class name, executed when instantiating objects.
  • this: Keyword referring to the current object instance calling the method/constructor.

14.1 Pillars Overview

  1. Encapsulation: Hide data via private access modifiers; expose safe access via public getters and setters.
  2. Inheritance (extends): Subclasses inherit non-private members from parent superclass. Use super() to invoke superclass constructor.
  3. Abstraction: Hide complete internal mechanics via abstract classes or interfaces.
  4. Polymorphism: Allow subclass instances to be referenced as parent superclass or interface types. Resolves methods dynamically at runtime via method overriding.

14.2 Aggregation vs. Composition

  • Aggregation: "Has-A" relationship where child objects can exist independently if parent is destroyed (e.g., Library has Books).
  • Composition: Strong "Part-Of" relationship where child objects are bound to parent's lifecycle (e.g., Car has an Engine).

15.1 Autoboxing & Unboxing

Primitives cannot be stored directly inside collections. Java uses Autoboxing (primitive to wrapper object, e.g., int to Integer) and Unboxing automatically.

20. Multi-Threading & Concurrency

text 
[ New Thread ] ---> .start() ---> [ Runnable ] <---> [ Running ]
                                       |                 |
                                    .sleep()         Completes
                                       v                 v
                                 [ Waiting ] ----> [ Terminated ]
java • MultiThreadingDemo.java 
class Worker implements Runnable {
    @Override
    public void run() {
        for (int i = 1; i <= 3; i++) {
            System.out.println(Thread.currentThread().getName() + " - Count: " + i);
            try { Thread.sleep(1000); } catch (InterruptedException e) {}
        }
    }
}

public class MultiThreadingDemo {
    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(new Worker(), "Thread-A");
        Thread t2 = new Thread(new Worker(), "Thread-B");

        t1.start();
        t2.start();

        t1.join(); // Wait for t1 to finish
        t2.join(); // Wait for t2 to finish

        System.out.println("All Threads Finished Execution.");
    }
}
