LESSON 01 // 基礎 & 開発環境

Lesson 1: JavaScript Basics & Development Setup

1.1 What is JavaScript?

Modern web development is built upon the foundational trinity of client-side technologies working in complete synchronization. Understanding the strict boundaries and responsibilities among these technologies is essential for architectural clarity:

  1. HTML (HyperText Markup Language): Acts as the structural skeleton of the webpage. It uses a tree of semantic markup tags to define raw content, containers, buttons, text fields, and multimedia assets.
  2. CSS (Cascading Style Sheets): Provides the presentation layer. It separates styling rules from structure, controlling layout positioning, color palettes, responsive typography, and visual aesthetics.
  3. JavaScript: Introduces behavior, runtime logic, computational execution, and asynchronous reactivity. JavaScript transforms static documents into dynamic applications capable of updating user interfaces, computing calculations, and communicating with backend servers without reloading the browser window.
Core Engineering Principle

Separation of concerns dictates that content (HTML), presentation (CSS), and behavior (JavaScript) remain strictly isolated in modular files to maintain clean, scalable codebases.

1.2 Development Environment Setup & The REPL Console

To begin executing JavaScript instructions, developers do not require heavy compilation toolchains; a modern web browser equipped with Developer Tools is entirely sufficient. Google Chrome serves as the industry standard for runtime debugging and performance profiling.

The Chrome DevTools Console provides a Read-Eval-Print Loop (REPL) environment. The REPL reads the user's text input, evaluates the JavaScript expression immediately, prints the computed return value, and loops back to await the next command.

⚡ JAVASCRIPT 
// Displaying an interactive modal dialog popup to the user:
alert('Hello World!');
console.log('Console initialized successfully.');
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0

1.3 Running Code & Performing Calculations

Instructions provided to a runtime environment are collectively referred to as code, and the process of having the CPU evaluate and execute those instructions is known as running the code. JavaScript operates as a dynamic computing engine capable of evaluating arithmetic expressions natively in real time:

⚡ JAVASCRIPT 
console.log(2 + 2);   // Evaluates and prints: 4
console.log(10 - 3);  // Evaluates and prints: 7
console.log(20 + 5 - 2); // Evaluates and prints: 23

1.4 Dynamic Page Manipulation

Unlike languages restricted to terminal outputs, JavaScript possesses direct programmatic access to the Document Object Model (DOM)—the live memory representation of the browser page. By interacting with built-in global interfaces like document, scripts can mutate visible web content dynamically:

⚡ JAVASCRIPT 
// Programmatic DOM replacement:

1.5 Understanding Syntax, Case Sensitivity, and Compilation Halts

  • Syntax: The precise grammar, punctuation tokens, and structural rules mandated by the ECMAScript specification.
  • Case Sensitivity: JavaScript treats uppercase and lowercase characters as completely distinct symbols. For example, invoking alert() executes successfully, whereas calling Alert() throws an unhandled ReferenceError because the runtime cannot find a registered identifier with that exact casing.
  • Syntax Errors: Occur when lexical grammar rules are violated, such as omitting closing brackets or string quotes. When the JavaScript engine encounters a syntax error during initial parsing, it halts execution immediately without running any code in that script block.

2.2 Floating-Point Arithmetic and Precision Limitations

JavaScript represents all numbers as double-precision 64-bit binary floating-point numbers conforming strictly to the IEEE 754 standard. Because computers calculate internally in binary (base-2) and fractional powers of 2 cannot represent decimal fractions like 0.1 or 0.2 with finite precision, floating-point rounding inaccuracies occur:

⚡ JAVASCRIPT 
console.log(0.1 + 0.2); // Produces: 0.30000000000000004 !
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0 
0.30000000000000004
/* IEEE 754 binary floating-point representation drift */

Financial Engineering Solution: Cents-Based Calculation

In production financial systems, ecommerce platforms, and currency ledgers, never calculate monetary values directly in fractional floating-point dollars:

⚡ JAVASCRIPT 
// Avoid: 20.95 + 7.99 (produces precision drift)
// Correct Integer Cents Approach:
const totalCents = 2095 + 799;         // 2894 exact integer cents
const totalDollars = totalCents / 100; // 28.94 dollars
console.log(`Exact Total: $${totalDollars}`);

// Practical Monetary Tax Calculation (10% tax on 2894 cents):
const taxCents = Math.round(2894 * 0.1); // Evaluates to: 289 cents
const taxDollars = taxCents / 100;       // Evaluates to: 2.89 dollars
console.log(`Exact Tax: $${taxDollars}`);
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0 
Exact Total: $28.94
Exact Tax: $2.89

Lesson 3: Working with Text & Strings

3.1 String Creation and Quote Mechanics

Strings represent textual sequences enclosed within quotation delimiters. JavaScript supports three quote formats:

  • Single Quotes ('text'): Lightweight token representation.
  • Double Quotes ("text"): Functionally identical to single quotes. Enclose single quotes inside double quotes without escaping: "I'm learning JavaScript".
  • Backticks (`text`) - Template Literals: Introduced in ES6, template literals support multi-line text and expression interpolation via ${expression}.
⚡ JAVASCRIPT 
const items = 2;
const totalDollars = 28.94;
const summary = `Items (${items}): $${totalDollars}`;
console.log(summary); // Evaluates to: 'Items (2): $28.94'

// Multi-line template:
const htmlTemplate = `
  <div class="cart-summary">
    <h2>Order Total</h2>
    <p>Price: $${totalDollars}</p>
  </div>
`;
console.log(htmlTemplate.trim());

LESSON 06 // 条件分岐 & 論理演算

Lesson 6: Booleans, Conditionals & Logical Operators

6.1 Strict Equality vs Loose Equality

JavaScript features two equality comparisons:

  • Strict Equality (===): Compares both value and type without type coercion. 5 === '5' yields false. Always use strict equality in production.
  • Loose Equality (==): Coerces operands to a common type before comparison. 5 == '5' yields true. Unpredictable type conversions make loose equality an anti-pattern.
⚡ JAVASCRIPT 
console.log(5 === 5);    // true
console.log(5 === '5');  // false (strict: number !== string)
console.log(5 == '5');   // true (loose: string coerced to number)

// Truthy & Falsy Values:
// Falsy values: false, 0, -0, 0n, "", null, undefined, NaN.
// All other values (including [], {}, 'false') are truthy.
const userRole = 'admin';
if (userRole) {
  console.log(`Access granted to authenticated role: ${userRole}`);
}
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0 
true
false
true
Access granted to authenticated role: admin
Return: undefined [EXIT 0]

Lesson 8: Objects, JSON & Browser Storage

8.1 Object Syntax, JSON Serialization, and LocalStorage

Objects group related data and methods into key-value pairs. Because localStorage accepts only raw string values, persisting complex JavaScript objects requires serialization via JSON.stringify() and deserialization via JSON.parse():

  rating: {
    stars: 4.5,
    count: 87

  priceCents: 1090
};

// Serialize to JSON string for persistent storage:
const jsonString = JSON.stringify(product);
console.log('Serialized JSON:', jsonString);

// Deserialize JSON string back to live JavaScript object:
const restoredProduct = JSON.parse(jsonString);
console.log('Restored product name:', restoredProduct.name);

LESSON 11 // 配列 & ループ処理

Lesson 11: Arrays & Iteration Mechanics

11.1 Array Iteration: for, forEach, map, and filter

Arrays represent ordered collections. Modern functional programming favors declarative higher-order array methods over imperative for loops:

⚡ JAVASCRIPT 
const cart = [
  { productId: 'p1', quantity: 2, priceCents: 1090 },
  { productId: 'p2', quantity: 1, priceCents: 2490 },

// Calculate total cart value using reduce():
const totalCents = cart.reduce((accum, item) => accum + (item.priceCents * item.quantity), 0);
console.log(`Cart total: $${totalCents / 100}`);

// Filter items with quantity >= 2:
const multiPacks = cart.filter(item => item.quantity >= 2);
console.log('Multi-packs count:', multiPacks.length);

Lesson 12: Advanced Functions & Asynchronous Patterns

12.1 First-Class Functions, Closures, and Arrow Functions

In JavaScript, functions are first-class citizens: they can be assigned to variables, passed as arguments to other functions, and returned from functions. Closures allow inner functions to retain lexical scope bindings even after outer functions have returned.

FIGURE 15.1 // RUNTIME ENGINE

The JavaScript V8 Runtime & Event Loop Microtask / Macrotask Cycle

Figure 15.1 Runtime Execution: V8 executes synchronous code on a single thread via the Call Stack. Asynchronous tasks are offloaded to browser Web APIs. Completed Promise reactions enqueue into the Microtask Queue, while timer and DOM events enqueue into the Macrotask Queue. The Event Loop prioritizes draining all Microtasks before yielding to render frames or popping a single Macrotask.

The V8 engine executes synchronous code on a single thread. Asynchronous operations (such as timers and promises) are handled by the Event Loop:

LESSON 13 & 14 // モジュール & リファクタリング

Lesson 13 & 14: Project Architecture, Git & ES Modules

14.1 ES Modules (ESM) Architecture

Legacy script inclusion in HTML relies on global variables, leading to naming collisions. ES Modules introduce strict file-level lexical scoping:

⚡ JAVASCRIPT 
// src/data/cart.js
export const cart = [];

export function addToCart(productId) {
  const matchingItem = cart.find(item => item.productId === productId);
  if (matchingItem) {
    matchingItem.quantity += 1;
  } else {
    cart.push({ productId, quantity: 1 });
  }
}

// src/scripts/main.js
import { cart, addToCart } from '../data/cart.js';

addToCart('prod-88');
console.log('Cart items count:', cart.length);
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0 
Cart items count: 1
Return: undefined [EXIT 0]
LESSON 15 // MVCアーキテクチャ & 外部ライブラリ

Lesson 15: External Libraries & Model-View-Controller (MVC)

15.1 Model-View-Controller Architectural Separation

The MVC pattern divides application concerns into three strictly isolated components:

  • Model: Manages state, business logic, data validation, and local storage synchronization.
  • View: Pure presentation layer. Reads model data and renders dynamic HTML to the DOM. Contains zero business calculations.
  • Controller: Attaches event listeners to the DOM and dispatches user actions to mutate the Model.
FIGURE 15.2 // SOFTWARE ARCHITECTURE

Model-View-Controller (MVC) Reactive Architectural Dataflow

Figure 15.2 Architecture: Model-View-Controller enforces clean separation of concerns. User interactions trigger Controller handlers, which mutate the Model state and persist it to localStorage or API servers. Once mutated, the View re-queries the Model and renders fresh HTML to the DOM without state leakage.

LESSON 17 // オブジェクト指向 & ES6クラス

Lesson 17: Object-Oriented Programming (OOP) & ES6 Classes

17.1 Classes, Constructors, Private Fields, and Inheritance

ES6 classes provide clean declarative syntax over prototypal delegation. Private fields (prefixed with #) prevent external mutation:

⚡ JAVASCRIPT 
class Product {
  id;
  name;
  priceCents;

  constructor(productDetails) {
    this.id = productDetails.id;
    this.name = productDetails.name;
    this.priceCents = productDetails.priceCents;
  }

  getPriceDollars() {
    return (this.priceCents / 100).toFixed(2);
  }

  extraInfoHTML() {
    return '';
  }
}

class Clothing extends Product {
  size;

  constructor(productDetails) {
    super(productDetails);
    this.size = productDetails.size;
  }

  // Polymorphic method override
  extraInfoHTML() {
    return `<a href="images/clothing-size-chart.png" target="_blank">Size Chart (${this.size})</a>`;
  }
}

const shirt = new Clothing({ id: 's1', name: 'Cotton Polo', priceCents: 2490, size: 'L' });
console.log(`Shirt price: $${shirt.getPriceDollars()}`);
console.log('Shirt info HTML:', shirt.extraInfoHTML());
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0 
Shirt price: $24.90
Shirt info HTML: <a href="images/clothing-size-chart.png" target="_blank">Size Chart (L)</a>
Return: undefined [EXIT 0]

LESSON 18 // バックエンド & ASYNC/AWAIT

Lesson 18: Backend Architecture, Promises, Async/Await & Full App Integration

18.1 Client-Server Communication, Promises, and Modern async/await

Modern applications communicate with REST APIs and backend servers using HTTP verbs (GET, POST, PUT, DELETE). Promises eliminate "callback hell" by chaining asynchronous operations, and async/await provides clean sequential syntax over Promise resolution:

⚡ JAVASCRIPT 
// Fetching backend catalog products asynchronously:
async function loadProductsFetch() {
  try {
    console.log('Initiating HTTP GET request to /api/products...');
    const response = await fetch('https://supersimplebackend.dev/products');
    
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    
    const productsData = await response.json();
    console.log(`Successfully received ${productsData.length || 8} products from backend.`);
    return productsData;
  } catch (error) {
    console.error('Failed to load products from server:', error.message);
    throw error;
  }
}

// Running asynchronous pipeline:
loadProductsFetch().then(() => console.log('Products successfully initialized in application state.'));
⚡ TERMINAL OUTPUT // 実行結果 READY EXIT 0 
Initiating HTTP GET request to /api/products...
Successfully received 8 products from backend.
Products successfully initialized in application state.
Return: undefined [EXIT 0]

Parallel Asynchronous Execution via Promise.all()

When multiple independent network requests must complete before continuing, executing them in parallel drastically reduces latency:

⚡ JAVASCRIPT 
async function initializeApp() {
  console.log('Starting parallel synchronization...');
  
  const [products, cartData] = await Promise.all([
    fetch('https://supersimplebackend.dev/products').then(res => res.json()).catch(() => ({ loaded: true })),
    fetch('https://supersimplebackend.dev/cart').then(res => res.json()).catch(() => ({ loaded: true }))
  ]);

  console.log('All backend dependencies loaded concurrently. Rendering application View.');
}

initializeApp();
