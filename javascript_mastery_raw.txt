Lesson 1: JavaScript Basics & Development Setup
1.1 What is JavaScript?
Modern web development is built upon the foundational trinity of client-side technologies working in complete synchronization.
Understanding the strict boundaries and responsibilities among these technologies is essential for architectural clarity:
1. HTML (HyperText Markup Language): Acts as the structural skeleton of the webpage. It uses a tree of semantic markup tags
to define raw content, containers, buttons, text fields, and multimedia assets.
2. CSS (Cascading Style Sheets): Provides the presentation layer. It separates styling rules from structure, controlling layout
positioning, color palettes, responsive typography, and visual aesthetics.
3. JavaScript: Introduces behavior, runtime logic, computational execution, and asynchronous reactivity. JavaScript transforms
static documents into dynamic applications capable of updating user interfaces, computing calculations, and communicating
with backend servers without reloading the browser window.
Core Engineering Principle: Separation of concerns dictates that content (HTML), presentation (CSS), and behavior (JavaScript)
remain strictly isolated in modular files to maintain clean, scalable codebases.
1.2 Development Environment Setup & The REPL Console
To begin executing JavaScript instructions, developers do not require heavy compilation toolchains; a modern web browser
equipped with Developer Tools is entirely sufficient. Google Chrome serves as the industry standard for runtime debugging and
performance profiling.
The Chrome DevTools Console provides a Read-Eval-Print Loop (REPL) environment. The REPL reads the user's text input,
evaluates the JavaScript expression immediately, prints the computed return value, and loops back to await the next command.
// Displaying an interactive modal dialog popup to the user:
alert('Hello World!');
1.3 Running Code & Performing Calculations
Instructions provided to a runtime environment are collectively referred to as code, and the process of having the CPU evaluate
and execute those instructions is known as running the code. JavaScript operates as a dynamic computing engine capable of
evaluating arithmetic expressions natively in real time:
2 + 2;   // Evaluates and prints: 4
10 - 3;  // Evaluates and prints: 7
1.4 Dynamic Page Manipulation
Unlike languages restricted to terminal outputs, JavaScript possesses direct programmatic access to the Document Object Model
(DOM)—the live memory representation of the browser page. By interacting with built-in global interfaces like document , scripts
can mutate visible web content dynamically:
document.body.innerHTML = 'Hello World';

1.5 Understanding Syntax, Case Sensitivity, and Compilation Halts
Syntax: The precise grammar, punctuation tokens, and structural rules mandated by the ECMAScript specification.
Case Sensitivity: JavaScript treats uppercase and lowercase characters as completely distinct symbols. For example, invoking
alert() executes successfully, whereas calling Alert() throws an unhandled ReferenceError because the runtime cannot
find a registered identifier with that exact casing.
Syntax Errors: Occur when lexical grammar rules are violated, such as omitting closing brackets or string quotes. When the
JavaScript engine encounters a syntax error during initial parsing, it halts execution immediately without running any code in
that script block.
Lesson 2: Numbers & Mathematical Operations
2.1 Basic Arithmetic Operators
JavaScript provides core binary and unary arithmetic operators for numerical computation, adhering to standard mathematical
expectations:
Addition ( + )
Subtraction ( - )
Multiplication ( * )
Division ( / )
10 + 5; // 15
10 - 5; // 5
10 * 3; // 30
10 / 2; // 5
2.2 Numerical Types: Integers vs. Floats
In standard JavaScript, all numerical values—whether whole numbers or decimals—are stored under a single unified numeric type
known as the IEEE-754 double-precision 64-bit float:
Integers: Whole numbers lacking fractional parts (e.g., 1 , 42 , -7 ).
Floating-Point Numbers (Floats): Numbers containing decimal fractional components (e.g., 2.5 , 10.99 ).
2.3 Operator Precedence & Parentheses
When evaluating complex mathematical expressions containing multiple operators, JavaScript follows standard mathematical
order of operations (PEMDAS / Operator Precedence rules):
1. Parentheses (...) enforce highest execution priority.
2. Multiplication ( * ) and Division ( / ) are evaluated left-to-right.
3. Addition ( + ) and Subtraction ( - ) are evaluated left-to-right.
1 + 1 * 3;   // Evaluates to: 4 (Multiplication executes before addition)
(1 + 1) * 3; // Evaluates to: 6 (Parentheses force addition priority)
2.4 Floating-Point Precision Issues in Monetary Calculations
Computers represent data internally as binary bits (zeros and ones). Certain base-10 decimal fractions cannot be expressed with
finite binary fractions, leading to microscopic rounding anomalies in IEEE-754 floats:
0.1 + 0.2; // Evaluates to: 0.30000000000000004 (not exact 0.3)

Lesson 3: Working with Text & Strings
3.1 String Creation and Quote Mechanics
A string represents immutable textual data enclosed within matching quote delimiters. JavaScript supports three distinct literal
syntaxes:
1. Single Quotes ( 'hello' )
2. Double Quotes ( "hello" )
3. Template Strings (Backticks: `hello` )
Single and double quotes are functionally identical for literal text, but double quotes are especially useful when writing strings
containing apostrophes without needing manual backslash escapes:
"I'm learning JavaScript"; // Valid string literal without escape backslashes
3.2 String Concatenation & Type Coercion
The + operator serves a dual purpose: when applied to numbers, it performs addition; when applied to strings, it acts as a
concatenation operator, joining text fragments together:
'some' + ' ' + 'text'; // Evaluates to: 'some text'
Type Coercion: When a binary operation mixes a string and a non-string type (like a number) using + , JavaScript automatically
coerces the non-string operand into a string:
'hello' + 3;          // Evaluates to: 'hello 3'
'$' + 20.95 + 7.99;   // Evaluates to: '$20.957.99' (Left-to-right evaluation coerces early!)
'$' + (2095 + 799) / 100; // Evaluates to: '$28.94' (Parentheses force numerical addition first)
The unary typeof operator evaluates the data type classification of any runtime expression:
typeof 2;       // Evaluates to: 'number'
typeof 'hello'; // Evaluates to: 'string'

3.3 Escape Characters
A backslash ( \ ) acts as an escape character, allowing developers to include special control characters inside strings that would
otherwise break syntax rules:
\' : Escapes a single quote inside single-quoted strings.
\" : Escapes a double quote inside double-quoted strings.
\n : Inserts a literal newline carriage return into the string.
3.4 Template Strings (ES6 Backticks)
Template strings (delimited by backticks ` ) solve the limitations of traditional string concatenation by introducing two powerful
capabilities:
1. Expression Interpolation ( ${...} ): Embeds any valid JavaScript expression directly inside strings, eliminating tedious +
concatenation chains.
2. Multi-line Strings: Preserves actual line breaks inside the code block without requiring manual \n escape characters.
const items = 2;
const totalDollars = 28.94;
const summary = `Items (${items}):$${totalDollars}`; // Evaluates to: 'Items (2): $28.94'

Lesson 5: Variables & State Management
5.1 Variable Concept & Declarations
A variable is a named memory container holding a reference to a specific value. Modern JavaScript provides three declaration
keywords with distinct scoping rules:
const (Constant): Declares a block-scoped variable whose reference cannot be reassigned after initialization. This should be
the default choice for all variables to ensure immutability of references.
let : Declares a block-scoped variable whose value and reference can be reassigned over time.
var : Legacy function-scoped declaration. It suffers from scope hoisting bugs and lacks block scoping; avoid it entirely in
modern codebases.
let score = 0;             // Declaration and initialization
score = 5;                 // Reassignment permitted
const maxLives = 3;        // Immutable reference assignment
// maxLives = 4;           // TypeError: Assignment to constant variable
5.2 Variable Naming Rules & Conventions
1. Syntax Rules: Identifiers cannot start with numbers; cannot contain spaces or hyphens; cannot use reserved language
keywords (like let , class , function ). Permitted special characters are $ and _ .
2. Naming Conventions:
camelCase : Standard convention for variables and functions (e.g., cartQuantity , userTotalScore ).
PascalCase : Capitalizes the first letter of every word; reserved for constructor functions and ES6 classes (e.g.,
ProductModel ).
kebab-case : Hyphen-separated lowercase words used strictly in HTML attributes and CSS classes (e.g., cart-quantity-
display ).
5.3 Assignment Operators & Shortcuts
let count = 10;
count = count + 1; // Explicit reassignment
count += 1;        // Addition assignment shorthand
count++;           // Postfix increment operator
count--;           // Postfix decrement operator

Lesson 6: Booleans, Conditionals & Logical Operators
6.1 Boolean Literals & Comparison Operators
Booleans represent binary truth states: true or false . Comparison operators evaluate expressions directly into Booleans:
Greater than / Less than: > , <
Greater than or equal / Less than or equal: >= , <=
Strict Equality ( === ): Evaluates both value and data type equivalence without type conversion. Always use this operator.
Loose Equality ( == ): Coerces mismatched types before comparison (e.g., 5 == '5' is true). Avoid this operator.
Strict Inequality ( !== ): Verifies that values or data types do not match.
6.2 Conditional Branching: if, else if, else
Conditionals control program execution paths by evaluating whether expressions resolve to truthy or falsy states:
const age = 15;
if (age >= 16) {
    console.log('Eligible to drive');
} else if (age >= 14) {
    console.log('Eligible for learner permit');
} else {
    console.log('Ineligible to drive');
}
6.3 Logical Operators
Logical AND ( && ): Evaluates to true if and only if both operands are truthy.
Logical OR ( || ): Evaluates to true if at least one operand is truthy.
Logical NOT ( ! ): Inverts the boolean state of an operand.
6.4 Truthy vs. Falsy Values
Every JavaScript value coerces to either truthy or falsy in a boolean conditional evaluation context.
The exact list of falsy values in JavaScript comprises:
1. false
2. 0 (numeric zero)
3. '' or "" or `` (empty string)
4. NaN (Not a Number; invalid arithmetic result)
5. undefined (unassigned variable or missing property)
6. null (intentional empty value)
All other values—including negative numbers, empty arrays [] , and empty objects {} —evaluate strictly to truthy.
6.5 Short-Circuit Evaluation Patterns
1. Ternary Operator ( condition ? expr1 : expr2 ): Inline conditional expression used for concise variable assignment.
2. Guard Operator ( && ): Evaluates from left to right; halts execution if the first operand is falsy, otherwise evaluates and returns
the right operand.
3. Default Operator ( || ): Evaluates left operand; if truthy, returns it immediately; if falsy, falls back to evaluating the right
operand.
const userCurrency = selectedCurrency || 'USD'; // Falls back to 'USD' if selectedCurrency is falsy

Lesson 7: Functions & Parameters
7.1 Defining & Calling Functions
Functions encapsulate reusable blocks of logic into structured, callable units:
function greet() {
    console.log('Hello!');
}
greet(); // Function invocation
7.2 Parameters, Arguments & Defaults
Parameter: A placeholder variable defined in the function signature declaration.
Argument: The concrete value supplied to the function upon invocation.
function calculateTax(costCents, taxPercent = 0.1) {
    return costCents * taxPercent;
}
calculateTax(2000, 0.2); // Uses 0.2 -> returns 400
calculateTax(2000);      // Uses default 0.1 -> returns 200
7.3 Return Statements
The return statement yields a computed value back to the caller and terminates function execution immediately. If a function
lacks a return statement, it implicitly evaluates to undefined .
function pickComputerMove() {
    const randomNumber = Math.random(); // Generates float in range [0, 1)
    if (randomNumber < 1/3) {
        return 'rock';
    } else if (randomNumber < 2/3) {
        return 'paper';
    } else {
        return 'scissors';
    }
}

JSON is a standardized, language-independent text format derived from JavaScript object syntax.

8.3 Browser Persistence: localStorage

8.4 Auto-Boxing
Primitive values (strings, numbers, booleans) do not natively possess methods. When a method or property is accessed on a
primitive (e.g., 'hello'.toUpperCase() ), JavaScript temporarily wraps the primitive inside an internal object wrapper, executes the
operation, and discards the wrapper object.
8.5 Objects as References
Variables assigned an object do not store the object data directly; they store a memory reference pointing to the object's heap
location:
const object1 = { message: 'hello' };
const object2 = object1; // Copies reference pointer, not the object data
object2.message = 'updated';
console.log(object1.message); // 'updated' (Both point to the same heap object)
const object3 = { message: 'updated' };
console.log(object1 === object3); // false (Distinct memory references)

Lesson 14: ES Modules & Project Refactoring
14.1 The Need for ES Modules
Loading multiple JavaScript files via global <script> tags creates critical software engineering problems:
1. Global Namespace Pollution & Naming Collisions: If two files declare a variable named cart, the second overrides the first
and breaks runtime operations.
2. Order Dependency: Scripts must be listed in a precise manual order or dependent references fail.
14.2 ES Module Implementation
JavaScript modules encapsulate file scopes. Variables and functions defined in a file remain private unless explicitly exported:
<!-- HTML entry point enables module loader: -->
<script type="module" src="scripts/amazon.js"></script>
// In data/cart.js:
export const cart = [];
export function addToCart(productId) { /* ... */ }
// In scripts/amazon.js:
import { cart, addToCart } from '../data/cart.js';
14.3 Currency Formatting Utility Module
// utils/money.js:
export function formatCurrency(priceCents) {
    return (Math.round(priceCents) / 100).toFixed(2);
}

15.2 The MVC (Model-View-Controller) Architectural Pattern
MVC organizes application architecture into three decoupled layers:
1. Model: Encapsulates business data, data structures, storage mechanics, and domain rules ( data/cart.js ).
2. View: Consumes state from the Model and generates visual HTML rendered on the screen ( checkout/orderSummary.js ).
3. Controller: Captures user actions via event listeners, updates the Model, and requests the View to re-render.
15.3 Re-Rendering vs. Manual DOM Manipulation
Manual imperative DOM updates introduce synchronization bugs. Under MVC, actions simply update the Model and re-invoke
the rendering View function:
// Controller:
function updateDeliveryOption(productId, deliveryOptionId) {
    cart.updateDeliveryOption(productId, deliveryOptionId); // 1. Update Model
    renderOrderSummary();                                    // 2. Re-render View
    renderPaymentSummary();                                  // 3. Re-render View
}

    });
});

Lesson 17: Object-Oriented Programming (OOP) & ES6 Classes
17.1 Procedural to OOP Refactoring
Procedural architecture maintains standalone variables and standalone functions. OOP bundles state (properties) and actions
(methods) within coherent objects.
17.2 ES6 Classes & Constructors
Classes act as standardized blueprints for instantiating objects with shared structures and methods:
export class Cart {
    cartItems; // Public field
    #localStorageKey; // Private field
    constructor(localStorageKey) {
        this.#localStorageKey = localStorageKey;
        this.#loadFromStorage();
    }
    #loadFromStorage() {
        this.cartItems = JSON.parse(localStorage.getItem(this.#localStorageKey)) || [];
    }
    saveToStorage() {
        localStorage.setItem(this.#localStorageKey, JSON.stringify(this.cartItems));
    }
}
const customerCart = new Cart('cart-main');
17.3 Class Inheritance (extends & super)
Subclasses inherit fields and methods from parent classes while introducing specialized behaviors:
export class Product {
    id; name; priceCents;
    constructor(productDetails) {
        this.id = productDetails.id;
        this.name = productDetails.name;
        this.priceCents = productDetails.priceCents;
    }
    extraInfoHTML() { return ''; }
}
export class Clothing extends Product {
    sizeChartLink;
    constructor(productDetails) {
        super(productDetails);
        this.sizeChartLink = productDetails.sizeChartLink;
    }
    extraInfoHTML() {
        return `<a href="${this.sizeChartLink}" target="_blank">Size Chart</a>`;
    }
}

Lesson 18: Backend Architecture, Promises, Async/Await & Full App Integration
18.1 Client-Server Communication & HTTP
Web browsers (Front-End) communicate with remote servers (Back-End) through the HTTP protocol.
Request: Specifies HTTP Method (GET, POST, PUT, DELETE), target URL, headers, and payload.
Response: Contains Status Code (200 OK, 404 Not Found, 500 Server Error) and data payload (typically JSON).
18.2 From XMLHttpRequest to Fetch API
Modern applications use the standardized Fetch API , which returns a Promise:
fetch('https://supersimplebackend.dev/products')
    .then(response => response.json())
    .then(productsData => console.log(productsData));
18.3 Managing Asynchronous Complexity: Async / Await
async/await provides linear, readable, synchronous-style flow control over asynchronous promises:
export async function loadPage() {
    try {
        const response = await fetch('https://supersimplebackend.dev/products');
        const productsData = await response.json();
        await loadCartFetch();
        renderOrderSummary();
        renderPaymentSummary();

    }
}
